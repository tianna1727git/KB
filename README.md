# Payo Agent Studio

从零实现的 Markdown 知识与 SEO 内容生产工作台。独立站点、独立数据库和文件存储，未复制旧工作台业务数据。

## 功能

- 资料库：统一 Markdown 上传、PDF/Office/TXT 转换、分页搜索、原文件下载与切片确认入口。切片阶段填写来源、分类、地区、生效与到期日期，并控制对外引用与停用。
- 知识整理 Flow：知识整理 Agent 执行语义提取、跨章节条件关联、证据复核与潜在冲突检查；人工选择后保存为待确认知识，经来源页审核后正式检索。原有章节切片审核工具保留。
- 知识库：按账号隔离，全文/关键词/同义表达检索，依据来源版本、状态和有效期过滤。
- SEO文章生产 Flow：主题关键词、平台、读者、需求描述，研究检索，大纲确认，文章起草，内容检查，人工确认，Markdown交付。
- 四类逻辑 Agent：知识整理、研究策划、写作、检查。共用可配置模型接口，使用分离的指令、证据及输出结构。
- 单步持久化、失败重试、来源变化提示、任务修订冲突保护、每次正文生成或保存保留独立草稿版本及来源快照。

## 运行

Node 22.13+，pnpm。

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm dev
pnpm build
```

开发预览使用合成身份和隔离的本地D1/R2。生产构建移除开发身份分支，API必须接收宿主验证的登录身份。不得将生产Worker绕过宿主身份网关直接暴露。

数据库结构位于 `db/schema.ts`，生成的迁移位于 `drizzle/`。本地应用迁移：

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_mature_bug.sql
```

## 模型接入

在部署平台的服务端环境中配置：

- `AI_URL`：HTTPS、兼容Chat Completions的完整接口地址。
- `AI_MODEL`：模型名称。
- `AI_KEY`：Bearer密钥（接口无须认证时可省略）。

文章 Agent 需支持 `messages`、`response_format: {type:"json_object"}`、`max_tokens`，返回 `choices[0].message.content` JSON字符串。不要将密钥加入代码、Git或浏览器。配置后，已授权的知识正文和用户写作需求会发送到该服务，部署者应选择企业认可的服务。

研究阶段最多8个检索问题，最多10条主命中及相邻章节上下文和30条写作规则，上下文超过上限时明确停止。没有匹配证据不生成文章。修改最多两轮。每次模型请求55秒超时，响应最大500KB。

## 首期边界

- 没有接入真实模型时，资料入库、文本检索、任务创建可用；不会伪造Agent执行结果。生成链路的自动化测试使用模型替身。
- 切片正文保留上传文本，原文比对只验证切片覆盖，不证明来源本身正确。人工修改后需重新对照确认。
- 知识整理采用语义提取，保留原文引文与字符位置；旧版章节切片仍可人工编辑、合并或拆分。支持基础 PDF/Office 文本转换，OCR、多模态理解及向量检索尚未接入。
- 所有资料和任务按登录账号隔离。首期未提供跨账号团队审批、成员邀请或角色委派。
- 当前步骤在服务端执行，结果落库；关闭页面后后续自动衔接暂停，重新打开任务可以继续。未部署无人值守队列或后台调度器。
- 流程是固定模板，未提供低代码Flow编辑器。外部网页搜索、自动发布到官网CMS、历史版本恢复编辑尚未接入，草稿历史查看与下载已提供。
- 模型检查与有效引用标记不能证明市场表述绝对正确。人工确认后导出文章包，由官网编辑在CMS排版发布。

## 源码结构

- `app/page.tsx`：工作台、资料、知识、文章任务、Agent/Flow界面。
- `app/globals.css`：响应式视觉样式。
- `lib/studio/api.ts`：权限、存储、任务状态流转与执行。
- `lib/studio/knowledge.mjs`：切片、覆盖校验、检索和有效性。
- `lib/studio/agent.mjs`：Agent定义、指令与模型适配器。
- `tests/`：知识处理单元测试及完整API流程集成测试。

运行时新增的资料、文章、密钥与本地测试状态不提交仓库；用户指定的160份初始化 Markdown 清单随服务端源码保存。

## 资料库

资料库保存 ProductMarketingChina - 文档_MD.7z 中的 160 份 UTF-8 Markdown（1,829,040 字节），保留文件名及相对目录。原文在 R2，元数据在 D1 的 `library` 记录中；与已审核知识切片分开，不自动用于写作。支持文件名/目录搜索、目录筛选、阅读、原文和下载。附带图片与其他附件本期未导入。

服务端导入清单 `lib/studio/library-data.json` 为此资料集的初始化源，不放入 public；仅站点所有者邮箱可以初始化此资料集；导入后的文件与新增上传均按登录账号隔离读取。`POST /api/studio/libraryImport` 按 10 份分批、确定性记录 ID 防重复，可中断续跑。资料库首次打开时可补齐初始化；导入成功后日常读取来自 D1/R2。现有资料和任务不会被修改。

### 统一资料入口

资料库与资料管理合并为一个一级菜单。顶部提供 Markdown 直接上传及原文件解析两种操作，下面以同一列表显示原有160份、后续上传文件和已进入切片确认的资料。支持文件名/目录搜索、目录筛选、每页10/20/50条及前后翻页。已进入切片流程的相同 Markdown 按内容指纹合并显示，原始文件记录保留。

新上传原文件支持20 MB以内 PDF、DOCX、PPTX、XLSX、UTF-8 TXT，转换结果最大2 MB。PDF限100页文本层提取，不含OCR；发现无文本页时阻止保存不完整结果。Office按结构提取，保留章节/幻灯片/工作表、表格及Excel已保存值与公式，图片与复杂布局需人工核对。解析提示随文件保存，原始文件独立存入R2可下载。解析结果不是已审核知识，用户通过“切片与确认”补充来源、分类和对外引用权限后再入库。

## MVP：资料、知识、写作 Brief

- 资料库可选择当前页或全部待整理文件，逐份创建知识整理 Agent 任务。提取语义知识、实体及关键词，关联跨章节条件，并比较相关旧知识的潜在冲突；引文必须逐字存在于原文。完成结果可选择保存为待确认、内部使用，再通过原有来源页审核。该操作会调用模型；旧 `knowledgeImport` 规则接口仅保留兼容，前端整理按钮不再调用它。
- 知识库展示类型、实体、来源文件V版本、条目R修订、状态与关联条目；关联表示同源或共享实体，非等价/因果或已验证关系。MVP未接入向量数据库。
- 来源页可调整用途（事实/规则）、分类、有效期、引用权限；可上传资料新版本，待新版全部确认后旧版退出可用检索，历史原文及引用快照保留。
- 新 Brief 包含主题、平台、读者、写作规则和补充需求，先进入 Sources 阶段。本地同义词/全文检索最多展示60条节选，可选择1–20条作为研究与写作范围，不保证穷尽全部相关知识。模型阶段不再自动加入未选中的事实来源；有效品牌规则会独立应用。
- 模型生成和正文保存均形成V1/V2等草稿快照，保存标题、正文、大纲、SEO信息、写作规则、事实来源与规则来源及修订号。任务页面可查看下载每个新草稿版本。来源变化不会改写旧快照。
- 模型仍需部署者配置 AI_URL / AI_MODEL / AI_KEY。Sources文本检索、人工编辑、版本保存及下载不调用模型；知识整理会调用模型，研究规划/大纲、正文、检查及重写会分别调用模型。自动化测试使用替身，不代表已接通真实OpenAI服务。

验证覆盖批量整理幂等、账号隔离、分类编辑、Sources选择与过期限制、写作规则传递、草稿版本留存下载、来源V2替代及旧原文保留；另有CR/LF原文覆盖与实体关联单元测试。

## 知识整理 Agent（semantic-v1）

入口为资料库的“AI 整理为知识”和批量整理按钮。每个资料版本创建持久化任务：分批语义提取 → 条件关联 → 独立证据复核与潜在冲突检查。页面展示进度，完成后展示最终条目、原文证据、条件关联、冲突和遗漏提示；支持暂停后续步骤、显式重试失败步骤、重新打开继续。多文件依次执行；关闭页面会暂停浏览器中的自动衔接，任务和阶段结果保留。

可独立设置服务端 `KNOWLEDGE_AI_URL`、`KNOWLEDGE_AI_MODEL`、`KNOWLEDGE_AI_KEY`。未设置独立地址时回退文章模型配置；独立地址不继承文章密钥。知识模型必须支持 Chat Completions 的严格 `json_schema` 结构化输出。未配置模型时保存任务但不调用模型、不返回虚假知识。

- 模型只读取当前 Markdown、已提取条目和相关旧知识节选，不使用外部网页或自行补充业务事实。引文需逐字匹配指定原文块，字符位置由服务端计算。模型声称支持但引文未出现的数字会标记为不支持。引用位置准确不等于语义、事实、条件或完整性已验证。
- 单份资料最多160,000字符，每块最多3,500字符，每次提取3块；单次最多35条，整份最多200条。提取结果与上下文设显式上限，超限会停止并提示拆分资料，不静默截断原文。潜在冲突检查只比较最多24条相关旧知识的节选（每条最多3,000字符），不是全库核验。
- 按来源ID、正文指纹、流程版本和模型配置复用任务，已完成结果可重新打开而无需再次调用。失败不会自动重试；超时或失败仍可能由模型服务商计费。界面显示服务商已返回的输入、输出及总Token，不将缺失用量推断为零费用。
- 保存必须人工选择并确认，模型复核未通过的条目不能保存。跨章节关联保留条件原文，潜在冲突保留双方证据。新文档和条目原子保存，初始为待确认、内部使用，不覆盖旧知识；来源页审核与引用权限规则继续生效。
- 使用严格结构和逐字证据校验降低错误风险，不能承诺100%知识准确或全量覆盖。审计遗漏提示与逐块引用覆盖也不代表块内每个事实均被提取。

实现：`lib/studio/ingestion-agent.mjs`（模式、提示词与证据验证）、`lib/studio/ingestion-api.ts`（任务、缓存、阶段执行、用量和待确认保存）、`components/ingestion-results.tsx`（进度与结果）。无需数据库结构迁移，任务使用已有按账号隔离的记录存储。

新增测试覆盖伪造引文拒绝、跨章节证据约束、审计覆盖、失败显式重试、结果复用、账号隔离、未配置模型不调用、Token累加、旧知识保留、冲突传递及重复保存。集成测试使用模型响应替身，不代表真实模型输出质量已验证。

## 页面内配置 OpenAI（个人账号）

“Agent 与 Flow”的模型状态和知识整理任务的“去配置模型”均打开工作台设置。模型配置表单支持输入模型名称及 API Key，确认测试用量后点击“测试连接并保存”。连接测试只发送固定测试文字，使用与知识整理相同的严格 JSON Schema 请求方式；成功后启用个人配置，失败保留旧配置。首次建议使用默认 `gpt-4.1`，模型可用性仍以当前API账号权限为准。

个人配置优先于部署模型配置，供当前登录账号的四个 Agent 使用；停用个人配置后回退部署配置（若不存在则等待配置）。密钥通过HTTPS提交至本站，服务端用AES-256-GCM加密存入D1，AAD绑定用户身份；浏览器读取接口只返回模型名、已保存状态、测试时间及修订号，不返回密钥或密文。页面不使用localStorage、sessionStorage或URL保存密钥。接口拒绝跨站Origin，要求登录，并限制测试频率为每账号15秒一次，保存和停用均检查配置修订号。

部署需要设置秘密环境变量 `MODEL_SETTINGS_ENCRYPTION_KEY`，为64位十六进制的256位随机值。该值只保存在Sites服务端秘密环境中，不进源码或托管清单。必须保留该密钥才能解密已保存配置；不要随意轮换或清除。环境变量配置方式继续适用于已有部署。页面配置只允许OpenAI官方固定HTTPS接口，不支持自定义供应商地址。密钥授权、模型权限及API额度由用户在OpenAI开发者平台管理；本站配置不创建API Key或计费账户。

`tests/model-settings.integration.mjs` 使用Miniflare和模拟OpenAI响应，验证权限、加密、身份绑定、密钥不回显、配置生效、失败保留、缓存密钥复用、频率及修订冲突。没有使用真实API Key，也不代表用户账号已成功连通。

## 当前 demo：160份Markdown与拉美跨境101

左侧demo提供实际批量Markdown上传、结构解析切片、审核入库、主题/平台/Brief、Sources确认、研究大纲、正文检查和多版本迭代。默认主题“拉美跨境101”、平台“官网”。资料不自动初始化或清空；已有资料按指纹复用。切片阶段不调用模型，内容生成需要已配置且有额度的模型，不使用旧SWIFT预制草稿。

同一demo任务可通过`demoRebrief`保存新Brief，保留旧正文及Brief/来源快照，再重新检索和生成V2、V3等。历史版本可查看和下载。`demoState`仅返回当前账号资料元数据、任务及模型状态。无数据库迁移。完整操作说明见`demo/payo/演示步骤.md`；160份上传、旧知识保留、多Brief版本及失败恢复由`tests/demo.integration.mjs`覆盖（模型为替身）。
